### Insert with returningResult to fetch generated ID

Source: https://www.jooq.org/doc/3.21/manual/sql-building/sql-statements/insert-statement/insert-returning

Shows how to insert a record and fetch the generated ID using returningResult(AUTHOR.ID). The example also demonstrates inserting multiple values and requesting multiple fields, including trigger-generated values.

```java
// Add another author, with a generated ID
Record record =
create.insertInto(AUTHOR, AUTHOR.FIRST_NAME, AUTHOR.LAST_NAME)
      .values("Charlotte", "Roche")
      .returningResult(AUTHOR.ID)
      .fetchOne();

System.out.println(record.getValue(AUTHOR.ID));

// For some RDBMS, this also works when inserting several values
// The following should return a 2x2 table
Result<?> result =
create.insertInto(AUTHOR, AUTHOR.FIRST_NAME, AUTHOR.LAST_NAME)
      .values("Johann Wolfgang", "von Goethe")
      .values("Friedrich", "Schiller")
      // You can request any field. Also trigger-generated values
      .returningResult(AUTHOR.ID, AUTHOR.CREATION_DATE)
      .fetch();
```

### Configure jOOQ code generator in Gradle (Groovy)

Source: https://www.jooq.org/doc/3.21/manual/code-generation/codegen-configuration

Configure the jOOQ code generator in Gradle (Groovy DSL). Set excludes as a Java regular expression with alternatives separated by pipes, and optionally set inputSchema (cannot be combined with schemata). The generate block is empty here; target specifies the destination package and directory for generated classes.

```groovy
// All elements that are excluded from your schema (A Java regular expression.
// Use the pipe to separate several expressions). Excludes match before
// includes, i.e. excludes have a higher priority
excludes = """
     UNUSED_TABLE                # This table (unqualified name) should not be generated
   | PREFIX_.*                   # Objects with a given prefix should not be generated
   | SECRET_SCHEMA\.SECRET_TABLE # This table (qualified name) should not be generated
   | SECRET_ROUTINE              # This routine (unqualified name) ...
"""

// The schema that is used locally as a source for meta information.
// This could be your development schema or the production schema, etc
// This cannot be combined with the schemata element.
// 
// If left empty, jOOQ will generate all available schemata. See the
// manual's next section to learn how to generate several schemata
inputSchema = "[your database schema / owner / name]"
}

// Generation flags: See advanced configuration properties
generate {}
target {

  // The destination package of your generated classes (within the
  // destination directory)
  // 
  // jOOQ may append the schema name to this package if generating multiple schemas,
  // e.g. org.jooq.your.packagename.schema1
  // org.jooq.your.packagename.schema2
  packageName = "org.jooq.your.packagename"

  // The destination directory of your generated classes
  directory = "/path/to/your/dir"
}
}
}
```

### Gradle Kotlin configuration for SQL-based forced type matching

Source: https://www.jooq.org/doc/3.21/manual/code-generation/codegen-advanced/codegen-config-database/codegen-database-forced-types/codegen-database-forced-types-matching

Configure jOOQ code generation in Gradle using Kotlin DSL to rewrite Oracle columns with default 'Y' or 'N' to Boolean using a converter. The SQL query selects columns from all_tab_cols where data_default is 'Y' or 'N'.

```kotlin
import org.jooq.meta.jaxb.*


configuration {
  generator {
    database {
      forcedTypes {
        forcedType {

          // Rewrite types to BOOLEAN
          userType = "java.lang.Boolean"
          converter = "com.example.YNBooleanConverter"

          // All Oracle columns that have a default of 'Y' or 'N' are probably boolean
          sql = """
            SELECT owner || '.' || table_name || '.' || column_name
            FROM all_tab_cols
            WHERE data_default IN ('Y', 'N')
          """
        }
      }
    }
  }
}
```

### Configure DSLContext and execute a select statement

Source: https://www.jooq.org/doc/3.21/manual/sql-building/dsl-context

Shows how to create a DSLContext with a Connection and SQLDialect, then use it to construct and execute a select statement. The DSLContext holds a Configuration that is used internally by the statement for execution.

```java
// The DSLContext is "configured" with a Connection and a SQLDialect
DSLContext create = DSL.using(connection, dialect);

// This select statement contains an internal reference to the DSLContext's Configuration:
Select<?> select = create.selectOne();

// Using the internally referenced Configuration, the select statement can now be executed:
Result<?> result = select.fetch();
```
