### Join fetch associations using HQL

Source: https://github.com/hibernate/hibernate-orm/blob/7.4.13/documentation/src/main/asciidoc/introduction/Tuning.adoc

Uses a left join fetch in HQL to eagerly fetch the authors association for all Book entities, ordered by ISBN. Executes a single SQL select statement.

```java
List<Book> booksWithJoinFetchedAuthors =
        session.createSelectionQuery("from Book join fetch authors order by isbn")
            .getResultList();
```

### Enable batch and subselect fetching in a session

Source: https://github.com/hibernate/hibernate-orm/blob/7.4.13/documentation/src/main/asciidoc/introduction/Tuning.adoc

Enables batch fetching with a batch size of 5 and subselect fetching for the current session. Use when you need to enable these fetching strategies per session instead of globally.

```java
session.setFetchBatchSize(5);
session.setSubselectFetchingEnabled(true);
```

### Batching > JDBC batching

Source: https://github.com/hibernate/hibernate-orm/blob/7.4.13/documentation/src/main/asciidoc/userguide/chapters/batch/Batching.adoc

`hibernate.jdbc.batch_size`::
	Controls the maximum number of statements Hibernate will batch together before asking the driver to execute the batch.
	Zero or a negative number disables this feature.

`hibernate.jdbc.batch.builder`::
	Names the implementation class used to manage batching capabilities.
	It is almost never a good idea to switch from Hibernate's default implementation.
	But if you wish to, this setting would name the `org.hibernate.engine.jdbc.batch.spi.BatchBuilder` implementation to use.

`hibernate.order_updates`::
	Forces Hibernate to order SQL updates by the entity type and the primary key value of the items being updated.
	This allows for more batching to be used. It will also result in fewer transaction deadlocks in highly concurrent systems.
	Comes with a performance hit, so benchmark before and after to see if this actually helps or hurts your application.

`hibernate.order_inserts`::
	Forces Hibernate to order inserts to allow for more batching to be used.
	Comes with a performance hit, so benchmark before and after to see if this actually helps or hurts your application.

### Annotate a many-to-many association with @Fetch(SUBSELECT)

Source: https://github.com/hibernate/hibernate-orm/blob/7.4.13/documentation/src/main/asciidoc/introduction/Tuning.adoc

Requests subselect fetching for a collection or many-valued association. Has the same effect as @Fetch(SELECT) except after HQL or criteria query execution, where it can fetch associations more efficiently.

```java
@ManyToMany @Fetch(SUBSELECT)
Set<Author> authors;
```

### Join fetch associations using the criteria API

Source: https://github.com/hibernate/hibernate-orm/blob/7.4.13/documentation/src/main/asciidoc/introduction/Tuning.adoc

Uses the criteria API to create a query that fetches the authors association for Book entities, ordered by ISBN. Equivalent to the HQL join fetch example and executes the same SQL.

```java
var builder = sessionFactory.getCriteriaBuilder();
var query = builder.createQuery(Book.class);
var book = query.from(Book.class);
book.fetch(Book_.authors);
query.select(book);
query.orderBy(builder.asc(book.get(Book_.isbn)));
List<Book> booksWithJoinFetchedAuthors =
        session.createSelectionQuery(query).getResultList();
```
