### Error Responses

Source: https://github.com/spring-projects/spring-framework/blob/v7.0.5/framework-docs/modules/ROOT/pages/web/webflux/ann-rest-exceptions.adoc

A common requirement for REST services is to include details in the body of error responses. The Spring Framework supports the "Problem Details for HTTP APIs" specification, RFC 9457. The main abstractions for this support include ProblemDetail (representation for an RFC 9457 problem detail; a simple container for both standard fields defined in the spec, and for non-standard ones), ErrorResponse (contract to expose HTTP error response details including HTTP status, response headers, and a body in the format of RFC 9457), ErrorResponseException (basic ErrorResponse implementation that others can use as a convenient base class), and ResponseEntityExceptionHandler (convenient base class for a @ControllerAdvice that handles all Spring WebFlux exceptions).

### Web MVC > Exception Handling > @ExceptionHandler Return Values > Response Body Handling

Source: https://github.com/spring-projects/spring-framework/blob/v7.0.5/framework-docs/modules/ROOT/pages/web/webmvc/mvc-controller/ann-exceptionhandler.adoc

@ExceptionHandler methods support returning various types to handle error responses. The @ResponseBody annotation indicates that the return value should be converted through HttpMessageConverter instances and written directly to the response. Alternatively, HttpEntity<B> or ResponseEntity<B> can be returned to specify the full response including HTTP headers and body, which are also converted through HttpMessageConverter instances. For RFC 9457 compliant error responses, ErrorResponse or ProblemDetail types can be returned to render error details in the response body.

### Error Responses > Customization and i18n

Source: https://github.com/spring-projects/spring-framework/blob/v7.0.5/framework-docs/modules/ROOT/pages/web/webmvc/mvc-ann-rest-exceptions.adoc

It is a common requirement to customize and internationalize error response details. Customizing the problem details for Spring MVC exceptions is also considered good practice to avoid revealing implementation details. `ErrorResponse` exposes message codes for "type", "title", and "detail", along with message code arguments for the "detail" field. `ResponseEntityExceptionHandler` resolves these message codes through a `MessageSource` and subsequently updates the corresponding `ProblemDetail` fields accordingly, enabling both customization and internationalization of error responses.
