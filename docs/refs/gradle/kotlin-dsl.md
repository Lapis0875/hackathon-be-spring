### Using a version catalog in Kotlin DSL (build.gradle.kts)

Source: https://docs.gradle.org/current/userguide/version_catalogs.html

Reference a dependency from the version catalog using the generated type-safe accessor `libs.groovy.core` in the Kotlin DSL. The catalog is named `libs` and the dependency `groovy` is defined in `gradle/libs.versions.toml`.

```kotlin
dependencies {
    implementation(libs.groovy.core)
}
```

### Using version catalog in Kotlin DSL (build.gradle.kts)

Source: https://docs.gradle.org/current/userguide/best_practices_dependencies.html

Consumes the version catalog in a Kotlin build script. Uses `alias(libs.plugins.versions)` for the plugin and `libs.bundles.groovy` for the bundle. The `java-library` plugin is applied.

```Kotlin
plugins {
    id("java-library")
    alias(libs.plugins.versions)
}

repositories {
    mavenCentral()
}

dependencies {
    // SLF4J
    implementation(libs.slf4j.api)

    // Jackson
    implementation(libs.jackson.databind)
    implementation(libs.jackson.dataformatCsv)

    // Groovy bundle
    api(libs.bundles.groovy)

    // Commons Lang
    implementation(libs.commons.lang3)
}

```

### Declare dependencies with catalog provider and unwrapped value (Kotlin DSL)

Source: https://docs.gradle.org/current/userguide/version_catalogs.html

Shows both forms of using a version catalog accessor in a Kotlin DSL dependencies block: passing the Provider<MinimalExternalModuleDependency> directly and calling .get() to unwrap it. Both work identically in dependency declarations.

```kotlin
dependencies {
    // Provider<MinimalExternalModuleDependency>
    implementation(libs.groovy.core)
    // MinimalExternalModuleDependency
    implementation(libs.groovy.core.get())
}
```

### Declare dependencies with java-library plugin in Kotlin DSL (build.gradle.kts)

Source: https://docs.gradle.org/current/userguide/declaring_configurations.html

Apply the `java-library` plugin and declare dependencies using `implementation`, `testImplementation`, and `api` configurations. The `api` configuration exports dependencies to consumers, while `implementation` keeps them internal.

```kotlin
plugins {
    `java-library`
}

dependencies {
    implementation("org.hibernate:hibernate-core:3.6.7.Final")
    testImplementation("junit:junit:4.+")
    api("com.google.guava:guava:23.0")
}
```

### Use variantOf() with classifier in Kotlin DSL

Source: https://docs.gradle.org/current/userguide/version_catalogs.html

Use variantOf() at the dependency declaration site to specify a classifier for a version catalog dependency. This example uses the 'linux-x86_64' classifier.

```kotlin
dependencies {
    implementation(variantOf(libs.my.lib) { classifier("linux-x86_64") })
}

```
